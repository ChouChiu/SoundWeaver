# dolbytool

专为杜比全景声（Dolby Atmos）与多声道音频制作设计的视频素材生成工具。基于 Python (PySide6) 与 Node/Chromium 无头渲染器构建，支持一键将音频与歌词素材批量转化为多种可视化视频与音频分轨文件。

---

## 产物概览

工具支持独立勾选并导出以下各类素材文件：

| 产物类别 | 输出文件命名 | 格式 / 规格 | 说明与用途 |
| :--- | :--- | :--- | :--- |
| **音频分轨 (Stems)** | `<音频名>_<stem>.wav` | 24-bit WAV | 按声道布局提取或分离出的独立音轨（中置、环绕、顶部、分频等） |
| **ADM BWF 元数据** | `<音频名>_adm.wav` | 24-bit BWF / BW64 | 符合 ITU-R BS.2076-2 标准，包含完整对象轨迹与坐标信息，可导入 DAW 或查看器 |
| **封面渐变背景** | `<音频名>_gradient.png` | PNG | 提取封面主色调并向下压暗过渡，作为视频背景底图 |
| **滚动波形视频** | `<音轨名>.mp4` | H.264 / HEVC MP4 | 左右声道上下双轨水平滚动，红播放头居中，已播高亮 / 未播暗化 |
| **逐字动态字幕** | `<音频/歌词名>_lyrics.webm` | VP9 + Alpha (透明) | 单行居中动态歌词，Apple Music 风格逐字高亮与平滑淡入淡出 |
| **完整播放器视频** | `<音频/歌词名>_player.mkv` | H.264 / HEVC MKV，或 VP9 + Alpha WebM | AMLL Prebuilt Player 整页画面：封面、曲目信息、进度条、控件、流动背景与滚动歌词，可混入音频 |
| **3D 声场可视化** | `<音轨名>_soundfield.webm` | VP9 + Alpha (透明) | 3D 空间内实时展示全景声动态对象位置、电平与运动轨迹 |

## 核心功能

### 1. 杜比全景声解码与分轨提取
- **自主软解**：直接识别 E-AC-3 JOC（Dolby Digital Plus + Dolby Atmos）音频流，严格遵循 ETSI TS 103 420 规范完成对象重构，不依赖杜比官方闭源组件
- **多种渲染布局**：可渲染为 5.1 / 5.1.2 / 5.1.4 / 7.1 / 7.1.2 / 7.1.4 / 9.1.4 / 9.1.6，默认 5.1.4，在分轨面板的“全景声渲染布局”中选择，批量与单曲共用
  - 对象在扬声器行之间恒功率平移，只有一排顶置的布局（x.1.2）把所有升高对象放在这一排，无顶置布局（5.1 / 7.1）折叠到地面
  - 床声道在布局缺少对应扬声器时按其位置摆放（如 7.1 床的 Lb 在 5.1 中并入 Ls），5.X 床的环绕在带后环绕的布局中均分到侧环绕与后环绕
  - 对象轨迹缓存按布局分开保存，ADM BWF 导出不受布局影响
- **精确对齐与相位校正**：
  - 在 64 带 QMF 域重构动态对象，自动补偿编码端对 Ls/Rs 施加的 90° 相移，保持原始混音相位一致性。
  - LFE 低频声道直通，与主声道天然对齐；严格基于容器编辑列表（Edit List）裁齐时间轴，消除编码预热帧延迟。
- **多声道与立体声分轨**：
  - **Atmos / 多声道输入**：可提取 `surround`（环绕，含后环绕）、`center`（中置/人声）、`lfe`（低频）、`front`（前置左右）、`front_no_center`（频谱抵消中置的前置）、`back`（后环绕，7.1 及以上）、`wide`（前宽，9.1.x）、`height`（全部顶置缩混）、`height_front` / `height_rear`（顶部前后对，x.1.4 及以上）、`height_side`（顶部中置对，9.1.6）、`downmix`（立体声缩混）、`low` / `high`（分频高低音），可用分轨随布局变化
  - **多声道文件**：按 ffprobe 报告的声道布局（5.1、5.1.2、5.1.4、7.1、7.1.2、7.1.4、9.1.4、9.1.6）读取各声道，无法识别的 6 声道以上文件按前 6 声道的 5.1 处理
  - **立体声输入**：支持 Mid/Side 分离、中置提取与频谱伴奏分离。
- **ADM BWF 母带导出**：
  - 单次解码同时生成带 `axml`（BS.2076-2）与 `chna` 块的标准 ADM 文件，床声道记录为 DirectSpeakers，ISF 与动态对象记录为 Objects。
  - 超过 4 GiB 时自动无缝转为 64 位 RF64/BW64 格式。
- **高效并发与内存映射**：
  - 单遍流式解析元数据，多工作进程切段并行重建 QMF 滤波器状态；
  - 渲染结果直接通过内存映射（mmap）缓冲供给下游分轨，无需多次落地中间临时 WAV。

### 2. 封面渐变图生成
- 基于 k-means 聚类算法自动从封面图片中提取最具代表性的主色作为上部基色。
- 在保持相同色相的前提下平滑压暗作为底部基色，通过 FFmpeg `maskedmerge` + `smoothstep` 渲染出平滑过渡的高清渐变背景。

### 3. 滚动波形视频
- 左右声道分置上下两轨，经过动态范围压缩放大（compand）以突出波形细节。
- 深色背景搭配冷银色波形，中央固定红色播放头。播放头左侧（已播放部分）保持原始高亮，右侧（未播放部分）向背景色平滑暗化（默认保留 35% 亮度，支持自定义）。
- **两阶段渲染加速**：单次解码生成完整波形长图并预补两侧留白，随后按帧号窗口滑动裁剪，编码耗时极低。
- 支持 H.264 NVENC / HEVC NVENC / libx264 编码器，硬件编码不可用时自动回退至 CPU 编码。

### 4. 逐字动态歌词视频
- **单行居中呈现**：基于 AMLL（applemusic-like-lyrics）渲染引擎，歌词单行固定在画面正中央；换行时平滑淡入淡出，新行在首字起唱时刚好完全显现。
- **多字体回退机制**：支持配置字体优先级列表，每个文字按序选用首个包含对应字形的字体（可轻松实现中西文分流排版），列表为空时回退至系统无衬线字体。
- **翻译与样式微调**：翻译行亮度支持单独调节（默认 70% 避免过淡）；自动过滤音译与背景人声，保持视觉聚焦。
- **确定性并行渲染**：
  - 无头 Chromium 通过 CDP `BeginFrame` 确定性时钟驱动，多次输出像素级完全一致；
  - 时间轴切段分配给多个无头浏览器实例并行渲染并无损拼接；
  - 前奏、间奏等无歌词区间自动复用透明关键帧，跳过无效渲染。
- 输出带 Alpha 通道的 VP9 WebM 视频，可直接拖入剪辑轨道透明叠加。

### 5. 完整播放器视频
- **AMLL Player 同款画面**：直接使用 `@applemusic-like-lyrics/react-full` 的 `PrebuiltLyricPlayer`，横屏为左封面右歌词，竖屏（高大于宽）自动切换为移动端布局
- **背景渲染器**：Mesh Gradient 流体渐变（默认，可随源音频 50–120 Hz 低频律动）、Isolation 色块（可开明暗光波）、纯色、透明（仅 VP9）；流动速度、渲染比例、随机种子均可调
- **歌词参数**：字号预设、字重、字间距、逐字渐变宽度、模糊 / 缩放 / 弹簧动画开关、翻译 / 音译 / 交换 / 和声显示，字体沿用有序回退列表
- **信息与控件**：曲名、艺人、专辑默认取音频标签，其次取 TTML 元数据，也可手填；控件区可选播放按钮或音频频谱（由源音频逐帧 FFT 得到），可显示音量条、底部按钮、剩余时间与音质标签（全景声源自动显示 Dolby Atmos）
- **排版**：页面按设备像素比缩放后再放大到输出尺寸，横屏按 1080p 窗口排版，竖屏按约 400 px 宽的手机排版（与真机一致），也可手动设置界面缩放；长句折行时均衡各行长度，横屏歌词栏右侧留白可调（AMLL 默认 15%，本工具默认 3%，减少不必要的折行）
- **过滤非歌词信息**：默认去掉歌词开头的“歌名 - 艺人”标题行（连同其下的翻译来源说明）、作词作曲编曲制作人等制作信息，以及结尾的版权声明；只处理首尾连续的信息行，正文中带冒号的句子不受影响，英文只认常见的制作人员称谓以免误删“Baby: …”这类正文；不修改 TTML 文件，播放器视频与字幕视频均可在面板中关闭
- **纯音乐**：不提供歌词时，歌词区显示一行常亮的提示（默认“纯音乐，请欣赏”，可改），布局与有歌词的音轨一致；提示留空则使用 AMLL 的无歌词布局，只显示居中的封面；视频时长取源音频，批量与专辑中缺歌词的音轨同样按纯音乐生成
- **预览**：面板内可指定起点与时长，以一半分辨率、30 fps 快速渲染一小段并在应用内循环播放
- **编码与音频**：libx264 / H.264 NVENC / HEVC NVENC / VP9 透明，NVENC 不可用时回退 libx264；输出为 MKV，音频可转码（AAC，WebM 为 Opus）、原样复制（保留 E-AC-3 JOC 与 PCM 分轨）或不混入；混入的音轨可选源音频或任一分轨，按分轨种类记忆，所选分轨尚未导出时自动补上分轨任务
- **截图格式**：默认开启“快速截图”，不透明的输出以 JPEG（质量 95）从浏览器取帧，色彩范围转换为视频标准的有限范围，比无损 PNG 快约 1.6 倍（模糊背景的 PNG 压缩是每帧的主要耗时，加开浏览器也无法分摊），与 PNG 相比 SSIM 0.994；取消勾选则用无损 PNG；透明 VP9 始终用 PNG；本机有 NVIDIA 显卡时选 NVENC 编码器还能再快约 25%
- **显卡加速**：页面始终用显卡合成（ANGLE Vulkan），纯色背景也不例外，比软件合成快约一倍；每个分段一个浏览器，多个浏览器在同一块显卡上分时执行，8 个以上基本不再提速
- **确定性并行渲染**：背景按歌曲时间逐帧绘制，随机数固定种子；背景的随机构图在封面加载后另用独立的固定序列生成，并在第一帧前等封面取色完成，各分段的背景布局与颜色完全一致，接缝处不会跳变或从默认色淡入；WebGL 上下文丢失（多为显存不足）时直接报错而不输出闪烁画面；`performance.now` 替换为 BeginFrame 时钟，逐字高亮每帧对齐歌词时间，分段并行渲染的接缝与单段渲染一致（滚动弹簧可能差一帧相位）

### 6. 3D 声场轨迹可视化视频
- **空间声场还原**：在 5.8 × 3.1 × 5.8 的 3D 半透明房间与网格地表内，将 OAMD 动态对象映射为发光小球，中央呈现听者头部模型。
- **电平与位置联动**：小球实时随三维坐标平滑运动，亮度随 JOC 重建后的真实电平增益变化，低于静音门限（默认 -90 dBFS）自动平滑淡出。
- **音轨联动暗化**：支持按指定分轨（如环绕、中置、顶部等）独立生成声场视频。在分轨模式下，未分配给该分轨扬声器的对象会按所选渲染布局中的能量占比自动降低亮度（默认降至 25% 或完全隐藏），直观呈现各声道的声音分布。
- **多视角与自定义模型**：
  - 支持等轴测（Isometric，默认）、俯视（Top）、低角仰视（Angle）三种预设摄像机机位。
  - 支持导入自定义 `.glb` 听者头模（自动对齐朝向与着色），未指定时使用内置头部剪影。
- **GPU 硬件加速**：基于 Three.js + ANGLE Vulkan 驱动独显渲染，无独立显卡时自动切换至 SwiftShader。
- **电平与光晕**：对象亮度、光晕与大小随实时电平变化（-60 至 -10 dBFS），强度可调
- **运动轨迹与落地投影**：对象身后保留一段渐隐轨迹（默认 1.5 秒，对象瞬移时自动截断），并向地面投下虚线与圆环以便判断高度
- **着色与取景**：统一色调、按高度（地面冷、顶部暖）或按对象区分着色；机位按画面比例自动取景，房间始终完整居中，竖屏同样适用，可再手动缩放

## 分辨率

- 各视频产物单边最高 16384 px，单帧总像素受 FFmpeg 限制（约 2.68 亿），超出时开始前即提示
- 超过 8K 的声场画面自动分块渲染再拼接，避免 Chrome 缩小 WebGL 缓冲导致的裁切；线条宽度随画面短边等比放大
- 播放器背景画布长边限制在 4096 px（背景本身为模糊流体，拉伸无损观感），浏览器提高 GPU 显存预算，16K 画面也能完整栅格化
- H.264 NVENC 最大 4096 px、HEVC NVENC 最大 8192 px，超出时依次改用 HEVC NVENC、libx264

## 环境准备与依赖

### 1. 系统依赖
- **Python**：>= 3.11
- **FFmpeg**：需包含 `libvpx-vp9` 编码器支持（若需硬件加速建议启用 `h264_nvenc` / `hevc_nvenc`）
- **Node.js**（>= 18）或 **Bun**

### 2. Python 环境配置
PySide6 及其他 Python 依赖已配置在 `pyproject.toml` 中，推荐直接使用 `uv` 管理：
```bash
# 同步并安装项目依赖（含 PyPI PySide6 与 PySide6-Fluent-Widgets）
uv sync

# 或在已有虚拟环境中安装
uv pip install -e .
```

### 3. 构建前端渲染器
字幕与声场渲染器依赖前端模块，首次使用前需编译打包：
```bash
cd renderer
bun install && bun run build
cd ..
```
> **说明**：首次渲染时，程序会自动下载适用的 `chrome-headless-shell` 至 `~/.cache/dolbytool/chrome`（体积约 100 MB）。

## 使用指南

### 启动程序
```bash
# 直接启动桌面应用
uv run dolbytool

# 启动并直接载入音频与封面文件
uv run dolbytool /path/to/audio.m4a [/path/to/cover.jpg]

# 传入多个音频或一个文件夹时直接进入批量 / 专辑模式
uv run dolbytool /path/to/album/
```

### 操作流程
1. **载入文件**：将音频（`.m4a` / `.eac3` / `.wav` 等）或封面拖入窗口，程序会在后台自动解析音频元数据，并尝试自动读取内嵌封面及同名 `.ttml` 歌词。
2. **选择输出项**：在左侧“输出”列表中勾选需要生成的素材类型，点击对应条目即可在右侧配置具体参数（如分辨率、帧率、字体、分轨选择等）。如果配置有误，底部会显示红色提示。
3. **开始执行**：点击右上角 **“开始”**（快捷键 `Ctrl + Enter`）启动任务队列，按 `Esc` 可随时中止当前任务。
4. **查看进度与结果**：底部“任务”面板会实时显示各子任务的运行阶段、用时与执行状态。任务完成后，**双击任务项即可直接在系统文件管理器中打开输出文件**。

### 批量与专辑处理
左侧切换到 **“批量 / 专辑”** 标签页（菜单 `文件 > 批量添加音频` `Ctrl + Shift + B`，`添加专辑文件夹` `Ctrl + Shift + M`），也可以直接拖入多个音频或一个文件夹

- **批量**：列表中每首音轨都按右侧当前的参数各自规划任务，依次放进同一个任务队列；各音轨使用自己的内嵌封面（没有时取所在文件夹的封面图）与自动匹配的歌词
- **歌词匹配**：列表“歌词”列显示每首配到的 `.ttml`，标灰表示未找到
  - 查找范围：音频旁边与其中的 `lyrics` / `lyric` / `ttml` / `歌词` 子文件夹；音频在 `Disc 1` 一类碟片目录时，也查专辑目录及其歌词子文件夹
  - 模糊匹配：忽略大小写、括号内容（如 `[Dolby Atmos 768 kbps]`）、开头的音轨号与 `艺人 - ` 前缀，同时比较音频的标题标签与歌词内声明的曲名（AMLL 的 `musicName`、`ttm:title`），名称完全一致的优先
  - 一份歌词只分配给一首音轨，同等程度地符合多首时不自动分配，留给手动指定
  - “导入歌词”可一次选择多个 `.ttml`，也可直接把歌词文件拖到批量标签页，自动分配后会列出未能匹配的文件
  - 右键音轨可“指定歌词”、“不使用歌词”或“恢复自动匹配”
- **逐首校验**：列表“状态”列显示每首将生成的任务数；无法读取的音轨整首跳过，不满足条件的单项输出（如立体声音轨的声场视频）只对该音轨跳过，开始前会汇总确认
- **按音轨取值**：分轨与音轨勾选按声道键记忆，切换不同声道布局的音轨不会丢失；渐变图颜色取自每首自己的封面；播放器视频的曲名取自每首的标签，艺人与专辑名仍可统一填写覆盖
- **输出位置**：留空“输出根目录”时每首保存到各自旁边的 `<音频名>_stems`；指定根目录后每首保存到 `<根目录>/<音频名>/`
- **专辑模式**：添加文件夹时自动开启，也可手动勾选
  - 按碟号、音轨号排序（无标签时按文件名自然排序），文件夹可含 `Disc 1` 一类子目录
  - 所有音轨共用专辑封面：可手动指定，留空时依次使用文件夹内的 `cover` / `folder` / `front` 等图片与首个内嵌封面
  - 默认输出到 `<专辑目录>/<专辑名>_stems/<音频名>/`，专辑名留空时取标签中的专辑名，再退回文件夹名
  - 渐变图整张专辑只生成一张 `<专辑名>_gradient.png`，放在专辑输出目录下
  - 播放器视频的“专辑模式”可选每首单独、整张专辑连续播放或两者都生成；连续播放像歌单一样由同一个页面从头播到尾，生成 `<专辑名>_player.mkv`，切歌时曲名、进度条与歌词随之切换（AMLL 自带切换动画），背景与动态封面连续流动，各首音频无损拼接后混入，整张专辑同样分段并行渲染

### 动态封面
封面可以是 Apple Music 式的动态封面，即无音轨的循环视频（`.mp4` / `.mov` / `.m4v` / `.webm` / `.mkv`），拖入窗口或在封面栏选择即可，带音轨的视频仍按音频处理

- **播放器视频**：封面按歌曲时间循环播放；渲染前会把动态封面抽成静帧缓存到 `~/tmp/dolbytool/motion`（按输出尺寸各抽一份，保留最近 6 份），逐帧按时间切换，分段并行渲染时画面与顺序渲染逐像素一致
- **其余用途**：封面预览、渐变图取色与播放器背景取色都使用动态封面的首帧
- **批量与专辑**：文件夹内的动态封面不会被当作音轨；专辑模式下优先作为整张专辑共用的封面，同时存在方形与竖版时优先方形
- **限制**：播放器的封面框是方形，竖版动态封面会居中裁切；AMLL 竖屏的全屏沉浸式封面布局暂未启用

### 运行机制与容错
- **非阻塞式容错**：某项任务失败不会影响其他独立任务的正常执行，所有任务结束后会统一汇总报错信息。
- **并发调度**：波形视频编码限制最多 3 个并行，避免耗尽系统资源。
- **按需分轨渲染**：分轨提取与全景声解码仅计算被勾选的声道组；若波形视频勾选了未导出的分轨，任务队列会自动按需补齐前置分轨步骤。
- **原子写入保护**：所有输出文件在生成过程中均先写入同目录下的临时文件（`.<文件名>.partial.<扩展名>`），渲染完成后原子重命名替换，保证任务取消或异常时不会破坏已有成果。
- **缓存与状态保持**：全景声对象轨迹会自动缓存至临时目录（`~/tmp/dolbytool/cache`），避免声场视频重复解码音频；窗口尺寸、参数配置与勾选状态会自动持久化保存于 `~/.config/dolbytool/dolbytool.conf`。
